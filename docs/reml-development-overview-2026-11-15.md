# Developing `boldtailor.reml` through scientist-led, cross-model review

*Development and review on November 14–15, 2026.*

**NOTE**: This report was drafted by GPT-6 Astra using the coding harness transcripts, with minor edits by Russ Poldrack (who is the "scientist" referred to in the report).

The development of `boldtailor.reml`, a restricted maximum likelihood (REML) module for the [boldtailor](https://github.com/poldrack/boldtailor) package, illustrates both the usefulness and the limitations of AI coding agents. A collaborator ([Jeanette Mumford](https://github.com/jmumford) had initially developed an implementation of the REML algorithm for testing, and the scientist had used this code to develop some simulations of REML performance. A review of the code suggested that the implementation was scattered and inconsistent, so the scientist prompted development of separate package models.  Multiple agents produced modular code, extensive tests, and confident assessments, yet successive reviews uncovered errors that could change scientific conclusions. Progress came through a scientist directing the work, asking for evidence, and moving findings between models—including asking one model to review another model's repairs.

**How the review cycle improved the code.**

1. **The scientist challenged the starting architecture and validation.** During a code walkthrough, the scientist asked whether the agents had reimplemented REML instead of using an established library. Claude identified duplicated experiment-level solvers whose differing conventions could confound comparisons between independent-noise and autocorrelated-noise analyses. The scientist requested one reusable package module, limited its scope to the needed scalar variance model, and explicitly requested comparison with `statsmodels` and property-based tests. When the scientist challenged the need for a custom solver, Claude supplied a benchmark supporting its speed advantage. The resulting design retained an external solver and independent likelihood calculations as checks.

2. **Claude's tested implementation still admitted scientifically misleading results.** Codex reproduced cases in which the code reported a successful variance decomposition even though the data could not distinguish signal variance from noise variance; missed a better positive-variance solution and reported zero; and declared a signal absent after adding an offset that the nuisance model should remove. Claude repaired these with identifiability checks, broader optimization, and revised numerical tolerances. It also corrected Codex's account of the optimization failure: the original grid already bracketed the missed minimum, but the algorithm refined only the bracket around its best grid value. This was a useful correction of the reviewer as well as the code. [Initial review](review-2026-11-15-reml.md); [Claude's response](review-2026-11-15-reml-response.md).

3. **Claude's first numerical repair introduced another false “no signal” result.** Its new tolerance tried to account for an ill-conditioned nuisance design, but confused unequal column units with genuinely unstable geometry. Codex constructed a case where changing those units caused an exactly computed, nonzero residual to be rejected. Claude acknowledged the regression and its overly strong claim of restored invariance. The next repair normalized nuisance columns and distinguished numerical uncertainty (`unresolved`) from absence of residual signal (`no_signal`). It also exposed optimization fallbacks that the documentation had previously described too confidently. [Follow-up review](review-2026-11-15-reml-followup.md); [response](review-2026-11-15-reml-followup-response.md).

4. **Gemini added useful checks, but its assurance was broader than its evidence.** OpenCode's review found an exact optimum incorrectly marked as unrefined, overflow/underflow in numerical helpers, and repeated calculations. It fixed these with failing tests committed first. However, its assessment that the statistical core was “mathematically sound” did not establish numerical reliability: Codex's next review found consequential defects still present. The records demonstrate a missed-defect/assurance problem here, not a specific new statistical bug introduced by Gemini's patch. [Second red-team report](review-2026-11-15-reml-redteam2.md).

5. **A further scientific review found errors beyond the earlier counterexamples.** At the scientist's request, Codex concentrated on scientific validity and useful generated tests. It found that subtracting two large squared quantities could corrupt a small residual and shift a variance-ratio estimate by more than two orders of magnitude. It also found that an uninformative autocorrelation correction curve could produce an arbitrary extreme estimate, and that experiment outputs discarded qualifications on uncertain model selections. Repairs stabilized residual calculations, rejected non-identifying estimates, and carried provisional-selection flags into scientific summaries. [Scientific re-review](review-2026-11-15-reml-scientific-rereview.md); [response](review-2026-11-15-reml-scientific-response.md).

6. **Codex's autocorrelation repair then needed correction by Claude.** Codex rejected any correction curve that turned anywhere on its grid. Claude showed that a turn outside the range used for pooling could invalidate otherwise useful estimates: in one censored-data simulation, true autocorrelation of 0.4 yielded a pooled estimate of zero through the all-invalid fallback. Claude's first proposed replacement also went wrong: rejecting individual ambiguous values selectively biased the pooled median upward. It reported that failed attempt and replaced it with inversion along a monotone branch spanning the admissible range, preserving the ordering of observations. Passing hundreds of existing tests had not prevented either mistake. The scientific response records the revision; the later Claude transcript records the intermediate biased attempt.

**Where the scientist's expertise changed the result.**

The clearest fMRI-specific intervention came after the inversion repairs: “strong negative autocorrelation is not plausible for fMRI data. should that prior be incorporated into the code?” The scientist then requested a configurable lower limit of −0.2 and raised the upper cap from 0.8 to 0.95. Claude implemented `rho_range=(-0.2, 0.95)`, used it for pooling and the required monotonic portion of the correction curve, and exposed whether the pooled estimate hit a bound. Individual feature estimates can still be negative. This was an explicit domain-informed constraint, not a Bayesian prior or a value inferred from the tests.

Statistical judgment also shaped the process. The scientist asked whether normalizing nuisance columns would change fitted parameter scalings, prompting an explanation of why preserving their span preserves the intended adjustment. They challenged the unexplained `_NO_SIGNAL_FACTOR = 64.0`; Codex traced it to an unsupported heuristic and expanded the review's explanation of why it could erase resolvable variation. They repeatedly requested property-based testing and specifically directed the later review toward scientific validity rather than operational test coverage. Separately, questioning the arbitrary 8 MiB memory budget led to benchmarks and more accurate documentation of what that budget actually bounded.

The scientist also maintained the feedback loop: requesting written responses to findings, returning those responses to the reviewer, asking for cross-review of subsequent changes, and ensuring reproducing examples became lasting regression tests. The value was in reproducible disagreements and corrections, rather than agreement among agents.

**Outcome and limits.** The module gained stronger independent checks, more stable calculations, explicit uncertainty reporting, and fMRI-informed noise-estimation controls. The final Claude session reported 2,459 passing default-suite tests, one unchanged packaging failure, and 90 passing experiment tests. This case supports scientist-led cross-model review as a productive development practice; it does not establish that more models or more passing tests guarantee scientific correctness.
